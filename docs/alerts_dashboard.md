# Nessi Alerts Dashboard

The Nessi Alerts Dashboard provides a comprehensive interface for monitoring, managing, and responding to alerts generated by the Nessi data quality monitoring system.

## Features

### Alert Monitoring
- Real-time view of all active alerts
- Filtering by severity, status, and source
- Detailed alert information including timestamps, descriptions, and related metrics

### Alert Management
- Acknowledge alerts to indicate they are being addressed
- Resolve alerts once the underlying issue has been fixed
- Silence alerts for a specified duration to temporarily suppress notifications

### Alert Rules
- Create and manage alert rules based on metrics and thresholds
- Enable/disable rules as needed
- Delete rules that are no longer relevant

## Using the Alerts Dashboard

### Accessing the Dashboard
The alerts dashboard is available at the `/alerts` endpoint of your Nessi monitoring dashboard. If authentication is enabled, you will need to log in first.

### Alert List
The main view of the dashboard displays all alerts in the system. Each alert card shows:
- Alert name and description
- Severity (critical, warning, info)
- Current status (active, acknowledged, resolved, silenced)
- Source of the alert
- Timestamp when the alert was created
- Action buttons for managing the alert

### Alert Actions
For each alert, you can:
1. **Acknowledge**: Click the "Acknowledge" button to indicate you are aware of the alert and working on it
2. **Resolve**: Click the "Resolve" button when the underlying issue has been fixed
3. **Silence**: Click the "Silence" button to temporarily suppress notifications for this alert
   - Specify the duration (in hours) for which the alert should be silenced
   - Provide a reason for silencing the alert

### Alert Rules
The "Rules" tab of the dashboard allows you to manage alert rules:
1. **Create Rule**: Click "Add Rule" to create a new alert rule
   - Specify the metric to monitor
   - Set the threshold value
   - Choose the comparison operator (>, <, =, etc.)
   - Set the severity level
   - Add labels for categorization
2. **Manage Rules**: For each existing rule, you can:
   - Enable/disable the rule
   - Edit rule parameters
   - Delete the rule

## API Integration

The alerts dashboard integrates with the Nessi metrics server through the following API endpoints:

### Alert Endpoints
- `GET /api/alerts`: Retrieve all alerts
- `POST /api/alerts`: Create a new alert
- `POST /api/alerts/{id}/acknowledge`: Acknowledge an alert
- `POST /api/alerts/{id}/resolve`: Resolve an alert
- `POST /api/alerts/{id}/silence`: Silence an alert

### Alert Rule Endpoints
- `GET /api/alerts/rules`: Retrieve all alert rules
- `POST /api/alerts/rules`: Create a new alert rule
- `POST /api/alerts/rules/{id}/enable`: Enable an alert rule
- `POST /api/alerts/rules/{id}/disable`: Disable an alert rule
- `DELETE /api/alerts/rules/{id}`: Delete an alert rule

## Notification Channels

The alerts system can send notifications through multiple channels:
- Email notifications (HTML or plain text)
- Slack notifications via webhooks
- Custom webhook notifications for integration with other systems

Configure notification channels in the Nessi configuration file to receive alerts through your preferred channels.

## Best Practices

1. **Alert Severity**: Use severity levels appropriately
   - Critical: Requires immediate attention, significant impact on data quality
   - Warning: Potential issues that should be addressed soon
   - Info: Informational alerts that don't require immediate action

2. **Alert Descriptions**: Write clear, actionable descriptions that help users understand:
   - What triggered the alert
   - Potential impact
   - Recommended actions

3. **Alert Rules**: Create focused rules with appropriate thresholds
   - Avoid setting thresholds too low, which can lead to alert fatigue
   - Use labels to categorize alerts for easier filtering and management

4. **Regular Maintenance**: Periodically review and clean up:
   - Resolved alerts that are no longer relevant
   - Alert rules that are no longer needed
   - Silenced alerts that should be permanently resolved
