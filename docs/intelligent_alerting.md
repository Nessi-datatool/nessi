

The Nessi Intelligent Alerting System automatically creates and manages alert rules based on historical data patterns, trends, and anomalies. This document explains how the system works and how to use it effectively.

## Overview

The Intelligent Alerting System analyzes historical metrics data to automatically create alert rules based on:

1. **Outlier Detection**: Identifies metrics that deviate significantly from their normal range
2. **Trend Deviation**: Detects when metrics deviate from their expected trend
3. **Seasonal Patterns**: Recognizes and alerts on deviations from recurring patterns (hourly, daily, weekly)

## Features

- **Automated Rule Creation**: Automatically generates alert rules based on historical data patterns
- **Self-Learning**: Continuously adapts thresholds based on new data
- **Sensitivity Configuration**: Adjustable sensitivity to control false positive/negative rate
- **Multiple Detection Strategies**: Supports outlier detection, trend deviation, and seasonal pattern recognition
- **Auto-Disable Unused Rules**: Automatically disables rules that haven't triggered alerts for a configurable period

## Configuration

The Intelligent Alerting System can be configured through the `IntelligentAlertingConfig` struct:

```go
type IntelligentAlertingConfig struct {
    MinimumDataPoints     int           // Minimum data points required for analysis
    AnalysisPeriod        time.Duration // Time period to analyze for patterns
    UpdateFrequency       time.Duration // How often to update rules
    Sensitivity           float64       // Sensitivity factor (0.0-1.0)
    EnableOutlierDetection bool         // Enable outlier detection
    EnableTrendDeviation   bool         // Enable trend deviation detection
    EnableSeasonalPatterns bool         // Enable seasonal pattern detection
    AutoDisableUnusedRules bool         // Automatically disable unused rules
    DisableThreshold      int           // Number of days without triggering before disabling
}
```

## Integration with Nessi Monitoring

The Intelligent Alerting System is integrated with the Nessi Monitoring system:

```go
// Enable intelligent alerting when creating a monitor
options := monitoring.MonitorOptions{
    MetricsPort: 9090,
    AlertManager: alertManager,
    EnableIntelligentAlerting: true,
    IntelligentAlertingConfig: nil, // Use default config
}
monitor, err := monitoring.New(options)
```

## How It Works

### Outlier Detection

The system calculates the mean and standard deviation of historical metric values and creates alert rules for values that fall outside the expected range (typically mean ± 3 standard deviations, adjusted by sensitivity).

### Trend Deviation

The system uses linear regression to identify trends in metrics and creates alert rules to detect when metrics deviate significantly from their expected trend.

### Seasonal Pattern Recognition

The system identifies recurring patterns in metrics (e.g., higher values during business hours, lower at night) and creates alert rules to detect when metrics deviate from these patterns.

## Generated Rules

Rules generated by the Intelligent Alerting System are tagged with the following labels:

- `type: "intelligent"` - Indicates that the rule was generated by the intelligent alerting system
- `strategy: "outlier"|"trend_deviation"|"seasonal"` - Indicates the detection strategy used
- `generated: "true"` - Indicates that the rule was automatically generated
- Additional strategy-specific labels (e.g., `bound: "upper"|"lower"` for outlier detection)

## Example: Sudden Change Detection

The Intelligent Alerting System can detect different types of sudden changes in metrics:

1. **Constant Changes**: Gradual increases or decreases over time
2. **Sudden Spikes and Dips**: Temporary anomalies in the data
3. **Oscillating Patterns**: Alternating values that follow a pattern

For each type of change, the system creates appropriate alert rules with thresholds based on the historical data.

## Best Practices

1. **Start with Default Configuration**: Begin with the default configuration and adjust as needed
2. **Adjust Sensitivity**: Lower the sensitivity if you get too many false positives, increase it if you miss important alerts
3. **Review Generated Rules**: Periodically review the rules generated by the system to ensure they align with your needs
4. **Combine with Manual Rules**: Use intelligent alerting alongside manually created rules for critical systems

## Reporting Capabilities

The Intelligent Alerting System provides comprehensive reporting capabilities:

- **HTML Reports**: Interactive reports showing active alerts and their statuses
- **PDF Reports**: Static reports for sharing and documentation
- **JSON/CSV Export**: Data export for integration with other systems

Generate reports using the CLI:

```bash
nessi alerts report --format=html --output=alerts-report.html
nessi anomaly report --format=pdf --output=anomalies-report.pdf
```
